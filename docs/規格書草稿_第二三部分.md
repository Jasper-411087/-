# 規格書草稿：第二部分（程式相關）與第三部分進度

> 依目前程式內容整理，可複製到規格書對應章節後再潤飾。

## 遊戲程式架構介紹

本遊戲以 Godot 4.3 開發，採「場景（Scene）＋腳本（Script）」架構。三個全域單例（Autoload）負責跨場景的資料與流程，其餘腳本各自掛在對應場景上。

| 模組 / 類別 | 類型 | 用途 |
|---|---|---|
| GameState | Autoload | 保存目前關卡、血量、分數、連擊、各判定次數；定義所有數值常數與判定範圍 |
| SceneManager | Autoload | 場景切換與單線劇情流程控制 |
| Sfx | Autoload | 播放判定、通關、失敗音效 |
| MainMenu（main_menu.gd） | 場景腳本 | 主選單，開始新遊戲 |
| Story（story.gd） | 場景腳本 | 劇情過場，讀取 story.json 逐頁顯示 |
| Game（game.gd） | 場景腳本 | 遊玩主邏輯：計時、輸入、判定、勝敗檢查、HUD |
| NoteField（note_field.gd） | 場景腳本 | 繪製 4 條軌道、音符、判定文字 |
| Boss（boss.gd） | 場景腳本 | Boss 圖像與受擊、回血、擊敗動畫 |
| ChartLoader（chart_loader.gd） | 工具類別 | 讀取並排序譜面 JSON |
| Result（result.gd） | 場景腳本 | 結算畫面，決定進入劇情或重新挑戰 |

類別關係：

```
SceneManager ──切換──> MainMenu / Story / Game / Result
Game ──讀取──> ChartLoader ──> data/charts/phaseN.json
Game ──寫入判定結果──> GameState <──讀取── Result
Game ──控制──> NoteField（畫面）、Boss（動畫）、Sfx（音效）
Story ──讀取──> data/story.json，結束後呼叫 SceneManager
```

### GameState
- 主要屬性：`current_phase` 目前關卡；`player_hp` 玩家血量（0~100）；`boss_hp` Boss 血量；`score` 分數；`combo` / `max_combo` 連擊與最高連擊；`counts` 各判定次數；`total_objects` 總物量；`cleared` 是否通關
- 常數：`BOSS_HP` 各關 Boss 血量（200/400/700）；`WINDOW` 判定範圍（±70/110/135ms）；`PLAYER_HP_DELTA`、`BOSS_HP_DELTA`、`SCORE_DELTA` 各判定的數值變化
- 主要方法：`reset(phase)` 重設數值；`grade_for(diff)` 由時間差決定判定；`apply_judgement(grade)` 套用判定；`accuracy()` 計算準確率；`is_cleared()` / `is_failed()` 勝敗判斷

### SceneManager
- 主要方法：`go_to(name)` 切換場景；`new_game()` 從開場故事開始；`start_phase(n)` 開始／重新挑戰某關；`play_story(key)` 播放劇情；`story_finished(key)` 劇情結束後進入下一關；`continue_after_clear()` 通關後接下一段劇情

### Game
- 主要屬性：`notes` 音符陣列（時間 t、軌道 lane、Hold 長度 len、是否判定完 done、是否按住中 holding）；`song_time` 目前音樂時間；`song_length` 關卡長度；`audio_player` 音樂播放器
- 主要方法：`_advance_time()` 依音樂播放位置推進時間；`_hit_lane(lane)` 處理按鍵判定；`_update_hold(n)` Hold 尾端判定；`_judge(grade)` 套用判定並更新畫面；`_finish()` 結束關卡進入結算

## 遊戲機制實作說明

### 一、音樂時間與音符位置
所有判定以「音樂播放時間」為準。音樂播放時，每幀讀取播放位置（加上音訊緩衝補償）作為 `song_time`；音樂未開始（倒數 3 秒）時用幀時間累加。音符畫面位置：

```
y = 判定線Y − (音符時間 − song_time) × 捲動速度
```

### 二、按鍵判定
```
當玩家按下第 lane 軌：
    在該軌找出「未判定」且與 song_time 時間差最小的音符
    若找不到，或時間差 > 135ms：不處理（空按不扣血、不加分）
    時間差 ≤ 70ms → Perfect；≤ 110ms → Good；≤ 135ms → Bad
    若是 Hold：標記為「按住中」，等待尾端判定
```

### 三、Miss 判定
每幀檢查所有未判定音符，若 `song_time − 音符時間 > 135ms` 仍未被按下，自動判定為 Miss（Hold 頭、尾各算一次 Miss）。

### 四、Hold（長按）
頭判定後持續檢查按鍵：按到尾端（容許提早放開 110ms 內）判 Perfect；太早放開判 Bad。

### 五、數值更新

| 判定 | 玩家血量 | Boss 血量 | 分數 |
|---|---|---|---|
| Perfect | +1（上限 100） | −1 | +100 |
| Good | 不變 | −1 | +50 |
| Bad | −1 | 不變 | +10 |
| Miss | −5 | +1（上限為該關 Boss 血量） | 不變 |

準確率 = 總分 ÷（總物量 × 100），總物量 = Tap 數 + Hold 數 × 2。

### 六、勝敗檢查（每幀）
```
若 玩家血量 ≤ 0：立即失敗
否則若 音樂播完：
    Boss 血量 ≤ 0 → 通關，否則失敗
```
Boss 血量在歌曲中途歸零時，Boss 顯示為「當機」狀態，但仍需打完整首歌；之後若 Miss 讓 Boss 回血，則須再次打到 0。

### 七、由 MIDI 自動產生譜面（tools/midi_to_chart.py）
MIDI 記錄每個音的開始時間、音高與長度，因此可以直接產生和音樂完全對齊的譜面：
```
讀取 MIDI，依速度變化（tempo）把每個音換算成秒
把 35ms 內同時發生的音視為一組（和弦）
依序走過每一組：
    與上一個音符間隔 < 該關最小間隔 → 略過（控制密度）
    依這組最高音的音高決定軌道（低音在左、高音在右），避免太快的同軌連打
    Phase 2/3：和弦且距上次多押夠久 → 多押（最多 3 / 4 押）
    Phase 2/3：音長夠長 → Hold
    Phase 3：連續快速和弦 → 對拍（左 2 / 右 2 交替）
```
音檔由同一份 MIDI 以 fluidsynth 合成，並用相同的起訖時間、速度與開頭空白處理，經檢查音檔與第一個音符誤差在 10ms 以內。

### 八、劇情流程
劇情文字存在 `data/story.json`，分為 opening、after1、after2、ending 四段。劇情結束後由 SceneManager 進入下一關；結算畫面通關則接下一段劇情，失敗則重新挑戰同一關。

## 實作問題與解決方式（可參考）

| 問題 | 解決方式 |
|---|---|
| Godot 對變數型別推斷失敗而報錯（note_field） | 改為明確標註型別 |
| 只用幀時間累加，長時間遊玩可能與音樂不同步 | 音樂播放中改以音樂播放位置為準 |
| 規格書原本的判定範圍與程式不一致（50/100/150ms） | 統一由 GameState.WINDOW 管理，改為規格書數值 |
| Boss 血量一歸零就結束關卡，與規格書「音樂播完」條件不符 | 改為音樂播完才判定通關，中途歸零只改變 Boss 外觀 |
